# Sliding Window Revision Notebook

## 0. Sliding Window Recognition Framework

Before thinking about code, ask:

### Q1. Is the problem about a contiguous range?

Keywords:

```text
subarray
substring
contiguous
continuous
consecutive
```

If YES → Sliding Window candidate.

---

### Q2. Can I reuse information from the previous range?

Example:

```text
Window [1..5]
Window [2..6]
```

Instead of recomputing:

```text
Remove outgoing
Add incoming
```

If YES → Sliding Window becomes attractive.

---

### Q3. Does expanding the window change validity monotonically?

This is the most important recognition rule.

Ask:

> If I expand the window, can the constraint only get worse (or only get better)?

Examples:

```text
sum
product
cost
zero count
distinct count
operations needed
```

If YES:

```text
Once invalid,
keep shrinking until valid.
```

This is the hidden signal behind many advanced Sliding Window problems.

Examples:

| LC # | Constraint |
|--------|------------|
| 1004 | zeroCount <= k |
| 904 | distinct <= 2 |
| 713 | product < k |
| 209 | sum >= target |
| 1208 | cost <= maxCost |
| 1838 | operations <= k |
| 3835 | cost <= k |

# 1. Core Sliding Window Mental Model

Think:

```text
Right Pointer = Explorer
Left Pointer = Repair Engineer
```

Right pointer:

```text
Explores new search space
```

Left pointer:

```text
Repairs invalid windows
```

Golden invariant:

```text
Left never moves backward
Right never moves backward
```

Therefore:

```text
Each element enters once
Each element leaves once
```

Time Complexity:

```text
O(N)
```

# 2. Fixed Window

## Recognition

Keywords:

```text
length k
size k
window of size k
substring length k
```

Goal:

```text
Maintain exact window size
```

---

## Mental Model

Think:

```text
Gain incoming
Remove outgoing
Evaluate
```

There is NO validity condition.

The window size itself is the rule.

---

## Master Template

```cpp
for(int r = 0; r < n; r++)
{
    // EXPAND
    expand(arr[r]);

    // SHRINK
    if(r >= k)
    {
        shrink(arr[r-k]);
    }

    // EVALUATE
    if(r >= k-1)
    {
        evaluate();
    }
}
```

---

### What enters?

### What leaves?

```cpp

```

# 3. Dynamic Window

## Recognition

Keywords:

```text
longest
maximum
minimum
at most
distinct
duplicates
replace
flip
cost
budget
operations
```

Goal:

```text
Maintain validity
```

instead of size.

---

## Mental Model

Think:

```text
Expand aggressively
Repair only when broken
Evaluate valid windows
```

---

## Golden Question

Before solving:

> What makes the window invalid?

That sentence usually gives:

```cpp
while(invalid())
```

---

## Master Template

```cpp
int left = 0;

for(int right = 0; right < n; right++)
{
    // EXPAND
    expand(arr[right]);

    // SHRINK / REPAIR
    while(invalid())
    {
        shrink(arr[left]);
        left++;
    }

    // EVALUATE
    evaluate();
}
```

---

## Dynamic Window Questions

### What state am I maintaining?

Examples:

```text
frequency map
sum
product
cost
distinct count
zero count
operations
```

---

### What breaks validity?

Examples:

```text
zeroCount > k
distinct > 2
product >= k
cost > budget
operations > k
```

---

### How do I repair?

```cpp
shrink()
left++
```

---

### When do I evaluate?

Depends on pattern.

# 4. Dynamic Window Pattern Families

---

## Pattern A: Longest Valid Window

Keywords:

```text
longest
maximum
largest
```

Template:

```cpp
for(...)
{
    expand();

    while(invalid())
    {
        shrink();
    }

    answer = max(answer, windowSize);
}
```

Mental Model:

```text
Repair first
Evaluate later
```

Invalid windows cannot contribute.

## Pattern B: Minimum Valid Window

Keywords:

```text
minimum
smallest
shortest
```

Template:

```cpp
for(...)
{
    expand();

    while(valid())
    {
        answer = min(answer, windowSize);

        shrink();
    }
}
```

Mental Model:

```text
Valid window is already candidate
Compress aggressively
```

---

### Examples

| LC # | Problem |
|--------|----------|
| 209 | Minimum Size Subarray Sum |
| 76 | Minimum Window Substring |
| 1234 | Replace the Substring for Balanced String |

---

## Pattern C: Counting Windows

Keywords:

```text
count
number of subarrays
number of substrings
```

Template:

```cpp
for(...)
{
    expand();

    while(invalid())
    {
        shrink();
    }

    answer += (right-left+1);
}
```

Reason:

If:

```text
[left........right]
```

is valid,

then every subarray ending at:

```text
right
```

and starting between:

```text
left → right
```

is also valid.

Count:

```text
right-left+1
```

---

|--------|----------|
| 713 | Subarray Product Less Than K |
| 930 | Binary Subarrays With Sum |
| 1248 | Count Number of Nice Subarrays |
| 1358 | Number of Substrings Containing All Three Characters |
| 992 | Subarrays With K Distinct Integers |
| 3835 | Count Subarrays With Cost ≤ K |

# 6. Advanced Recognition: Cost-Based Sliding Window

Most people stop at:

```text
duplicates
distinct
frequency
```

Strong candidates recognize:

```text
cost
operations
budget
resource usage
```

as sliding window signals.

Ask:

> Can expanding only increase the cost?

If YES:

```text
expand
while(cost > budget)
    shrink
```

Examples:

| LC # | Problem |
|--------|----------|
| 1208 | Equal Substring Within Budget |
| 1838 | Frequency of Most Frequent Element |
| 3835 | Count Subarrays With Cost ≤ K |

# 7. O(N) Proof

Why not O(N²)?

Because:

```text
Right moves N times
Left moves N times
```

Total:

```text
2N
```

Therefore:

```text
O(N)
```

Never think:

```text
for + while = O(N²)
```

for Sliding Window.

The invariant is:

```text
Neither pointer ever moves backward.
```
