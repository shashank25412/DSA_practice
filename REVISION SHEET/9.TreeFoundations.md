
# Tree Recursion Notes (Phase 1 & Phase 2)

## Phase 1 — Recursive Function Contracts

### Core Mental Model
- Every node asks its children for help.
- Design the recursive function for the **parent**, not for the interviewer.
- Every node solves only **its own subtree**.
- The parent combines children's answers.

### Derivation Framework
1. Understand the problem.
2. Design the function contract.
3. Assume children solve their own subproblems.
4. Derive the base case.
5. Derive the combine rule.
6. Pseudocode.
7. Code.
8. Dry run.

### Checklist
- What does my parent need?
- What should I return?
- What is my recursive state?
- What is the smallest subtree?
- How do I combine left & right?

# Phase 2 — Information Flow

## Core Mental Model
- The recursive function does **not** always return the interview answer.
- Return what the **parent** needs.
- Decide whether the returned value can naturally become the final answer.
- Introduce global state only when it cannot.

## Information Flow Questions
- What information flows upward?
- What stays local?
- Does the parent need the final answer or an intermediate value?
- Can one return value encode multiple states?

## Sentinel Principle
Balanced Tree:
- height >= 0 → balanced
- -1 → unbalanced

One integer encodes both height and balance.

## Global Variable Decision
- Returned value reaches root naturally → No global.
- Final answer can occur anywhere and cannot propagate as parent's required value → Global needed.

## Interview Checklist
1. What does the parent need?
2. What should I return?
3. What is the recursive state?
4. What is the base case?
5. Pre-order work?
6. Post-order work?
7. Can the return value become the final answer?
8. If not, introduce global state.

## Three-Month Revision
- Parent > Interviewer.
- Contract before code.
- Return intermediate information, not necessarily the final answer.
- Global state only when the final answer cannot naturally flow to the root.
