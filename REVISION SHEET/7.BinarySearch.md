# Binary Search Foundations — Mental Model & Invariants

## Learning Goal

Do **not** memorize templates.

Develop the instinct to recognize:

* Search Space
* Monotonicity
* Boundaries
* Invariants
* Safe Elimination

---

# Core Mental Model

Most people think:

> Binary Search = Search in a sorted array

A deeper understanding is:

> **Binary Search = Boundary Finding over a Monotonic Search Space**

The sorted array is only one possible search space.

Later, you will binary search over:

* Indices
* Answer values
* Speeds
* Capacities
* Timestamps
* Feasible / Infeasible solutions

The underlying reasoning remains the same.

---

# The Fundamental Question

Binary Search is useful when:

> I can eliminate half the search space safely.

The key word is:

> Safely

Safe elimination requires:

> Monotonicity

---

# Monotonicity

A property is monotonic when it changes only once.

Examples:

```text
F F F F T T T T
```

or

```text
T T T F F F F
```

There is a boundary.

Binary Search efficiently finds that boundary.

---

# Binary Search Thinking Framework

Whenever you see a potential Binary Search problem, ask:

## 1. What is the Search Space?

Possible answers.

Examples:

```text
0 ... n-1
```

or

```text
1 ... 10^9
```

---

## 2. What is Monotonic?

Can every candidate be classified as:

```text
False or True
```

such that it changes only once?

Example:

```text
Version:
1 2 3 4 5 6

Bad?
F F F T T T
```

---

## 3. What Boundary Am I Looking For?

Possible goals:

* Exact Match
* First True
* Last False
* First ≥ Target
* First > Target
* Last ≤ Target

---

## 4. What Invariant Must Always Remain True?

An invariant is:

> A fact that remains true throughout the search.

Example:

```text
If the answer exists,
it must still lie inside [left, right]
```

Never eliminate the actual answer.

---

# Binary Search Families

| Family                       | Goal                 | Recognition Signal                    |
| ---------------------------- | -------------------- | ------------------------------------- |
| Exact Element Search         | Find exact target    | "Find x in sorted array"              |
| Boundary Search              | First / Last valid   | "Insert position", "first occurrence" |
| Dual Boundary Search         | Find range           | "First and last position"             |
| Rotated Search               | Broken monotonicity  | Rotated sorted array                  |
| Local Monotonicity Search    | Peak / Valley        | Peak element                          |
| Binary Search on Answer      | Search answer space  | Koko Eating Bananas                   |
| Optimization via Feasibility | Min/Max valid answer | Ship packages                         |

# Problem Progression

## LC 704 — Binary Search

### Why It Exists

Introduces:

* Search-space elimination
* Safe shrinking
* Invariants

### Family

Exact Element Search

### Search Space

Indices

```text
0 ... n-1
```

### Invariant

```text
If target exists,
it lies inside [left, right]
```

### Elimination Rule

If:

```cpp
nums[mid] < target
```

then:

```text
Everything ≤ mid is impossible
```

Move:

```cpp
left = mid + 1
```

### Interview Instinct

Trigger when you see:

```text
sorted array
find target
O(log n)
```

---

## LC 35 — Search Insert Position

### Why It Exists

Introduces:

> Boundary Thinking

We are no longer searching for an exact target.

We are searching for:

```text
First element ≥ target
```

### Family

Boundary Search

### Search Space

Indices

### Invariant

```text
The first valid insertion position
lies inside [left, right]
```

### Boundary

```text
First element ≥ target
```

### Interview Instinct

Trigger when you see:

```text
insert position
lower bound
first valid position
```

---

## LC 278 — First Bad Version

### Why It Exists

Introduces:

> First True Boundary

The most important Binary Search pattern.

### Family

Boundary Search

### Search Space

Versions

```text
1 ... n
```

### Monotonic Pattern

```text
F F F F T T T T
```

### Invariant

```text
First bad version
lies inside [left, right]
```

### Key Insight

If:

```cpp
isBad(mid) == true
```

Do NOT discard mid.

Because:

```text
mid may be the first bad version
```

Move:

```cpp
right = mid
```

### Interview Instinct

Trigger when you see:

```text
first valid
first bad
minimum satisfying condition
```

# Universal Binary Search Invariant

Most Binary Search problems reduce to:

```text
The answer still exists inside [left, right]
```

Everything else is a specialization.

---

# Movement Cheat Sheet

## Rule

> If mid can still be the answer, keep it.

Otherwise:

> Eliminate it.

---

| Goal           | Mid Valid? | Keep Mid? | Move        |
| -------------- | ---------- | --------- | ----------- |
| Exact Search   | Found      | Yes       | Return      |
| First True     | True       | Yes       | right = mid |
| Last False     | False      | Yes       | left = mid  |
| First ≥ Target | Yes        | Yes       | right = mid |
| Last ≤ Target  | Yes        | Yes       | left = mid  |

# Binary Search Instinct Checklist

Before choosing Binary Search, ask:

### 1. What is the search space?

```text
Indices?
Answer values?
```

---

### 2. Can I classify candidates as:

```text
False / True
```

with only one transition?

---

### 3. What boundary am I looking for?

```text
Exact?
First True?
Last False?
Lower Bound?
Upper Bound?
```

---

### 4. What invariant must remain true?

```text
The answer still lies inside [left, right]
```

---

### 5. Can mid still be the answer?

If yes:

```text
Keep mid
```

If no:

```text
Discard mid
```

---

# 3-Month Recall Version

Remember only this:

```text
Binary Search is not searching.

Binary Search is shrinking.

It shrinks a monotonic search space
while preserving an invariant
until only the boundary remains.
```
